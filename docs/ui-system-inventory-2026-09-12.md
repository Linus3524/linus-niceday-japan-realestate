# UI 三層整理與現況盤點

這份整理以目前已經發展出的功能為起點，將可保留的設計正式納入系統。初始盤點沒有修改畫面；後續第一批實作進度見文末。涉及資訊重排的項目仍是候選，需以實際桌機／手機畫面驗證。

## 第一層：全站共同規則

| 項目 | 整理原則 | 現況與影響 |
| --- | --- | --- |
| 字體 | 介面與資訊閱讀以既有 Noto Sans TC／JP 為共同基礎；日文名稱沿用字形切換 | `index.css` 對所有 h1–h6 套用 serif，與元件內的 sans 設定交錯，標題實際結果受繼承影響。先檢查閱讀頁的角色，再處理全域規則 |
| 標題角色 | 分頁導言、功能區塊、卡片小節可以有不同大小；同一角色保持一致 | 已有 `PageIntroCard`、`SectionHeading`、`listing-section-title`，應保留各自用途，不全部改成同一種標題 |
| 文字層級 | 結論／主要金額最突出，解釋次之，來源最末；重要限制與操作標籤不能被當作小字 | 診斷區有較多 10–11px 文字。需逐項判斷內容重要性，不能只因為是附註就縮小 |
| 邊框與形狀 | 一般卡片、表單與按鈕延續直角；圖紙地圖的膠囊標記保留為功能例外；標準分隔採 1px `#DDE3DF`，深墨邊框用於主要操作或較高層級 | 流程節點、摘要小點、tooltip 與 CSS 仍有圓角。`rounded-none` 雖然是 0px，也要注意原要求禁止所有 `rounded-*` 類別；以無圓角預設表達 |
| 品牌 | `#007D5A` 負責主要操作與識別，`#1A2A22` 負責主文字；明亮綠作輔助或互動狀態 | 既有 `primary` 指向 `#00A174`，`primary-deep` 才是 `#007D5A`。先確定角色，再逐處遷移，避免直接替換全站色碼 |
| 間距 | 定義頁面、區塊、卡片、列內四種間距角色；密集明細可有緊湊版本 | 現有 p-4／p-6／p-8 等不必全部消除；同樣用途才收斂，手機與桌機分開檢查 |
| 操作 | 主要／次要／文字操作各有固定樣式，選取、焦點、停用、載入要可辨識 | 先從計算器與圖紙分析操作整理，再擴至指南；維持既有觸控範圍、keyboard focus 與防重複行為 |
| 圖示 | 介面圖示使用 Lucide，大小隨標題或操作角色固定 | `PageIntroCard` 已有 Lucide 名稱映射，但未知字串仍退回 Material Symbols；需先盤點呼叫者再移除備援 |

字級與間距的精確數值在第一批實際畫面比對時確定。這份盤點不以全域 CSS 強制覆蓋所有元件，也不把第三方地圖控制、外嵌貼文與品牌圖片當成本地卡片直接改寫。

## 第二層：相同資訊共用呈現規則

### 先把顏色的角色分開

| 角色 | 適用內容 | 規則 |
| --- | --- | --- |
| 品牌與操作 | 主要按鈕、選取狀態、功能識別 | 沿用品牌綠；不靠綠色本身宣稱投資安全或結果保證 |
| 評估程度 | 可行性、價格診斷、注意事項 | 可沿用綠、琥珀、磚紅與中性色的程度關係，必須伴隨原有文字／圖示；共用程度樣式不等於不同領域的結論相同 |
| 資料狀態 | 未填、未載明、估算、無資料、取得失敗 | 與評估結果分離；不能把未取得資料畫成低風險或零費用 |
| 資訊分類 | 格局、設備、交通、預算等條件標籤 | 可保留分類色，但不能用分類色間接表示風險程度 |
| 圖表系列 | 本案開價、成交基準、在售基準 | 可以使用專屬比較色；固定圖例與文字名稱，不能讓系列色冒充好壞判斷 |

具體混用出現在 `RequirementAssessment.tsx`：`badgeStyle` 直接使用 `criteriaTagStyle`，例如「需要取捨」使用格局色、「較難兼顧」使用預算色。後續應拆開分類與程度的樣式來源，維持原判斷公式與結果文字。

`listing/statusTheme.ts`、`RequirementAssessment.tsx`、`CrimeSafetyCard.tsx` 已有各自的狀態配置，可以共享基礎視覺色階，但各領域仍保留自己的標籤、分級與說明。價格「待確認」與需求「資料不足」的目前色彩也不同，適合一併整理資料狀態。

### 可重複使用的資訊形式

| 資訊形式 | 共用部分 | 保留的領域差異 |
| --- | --- | --- |
| 金額摘要 | 標籤、主值、單位、期間、補充說明的位置與字級 | 日圓／萬円、月付／總價、已知小計／估算範圍；完全沿用原格式化與四捨五入函式 |
| 費用明細 | 項目、金額、依據、待確認狀態與合計層級 | 租賃與買賣的項目、日割、押金、稅費及假設不能因共用樣式而合併算法 |
| 結論與下一步 | 結論先出現、證據次之、建議最後；程度徽章有固定樣式 | 價格、治安、可行性保留不同判斷與用詞 |
| 資料來源 | 名称、期間、樣本量、估算標記的共同層級 | MLIT、在售快照、治安町丁目／都道府縣精度與更新時間分別交代 |
| 載入／錯誤／空值 | 統一標題、文字、圖示與重試操作樣式 | 依各功能顯示真正原因，不用通用提示掩蓋圖紙未載明、定位失敗或沒有路線 |
| 開合區塊 | 箭頭、焦點、展開狀態與標題位置 | 哪些內容預設展開依閱讀目的決定；費用未知、重要風險與必要操作不應只藏在收合內容 |

先整理這些視覺模式，再決定哪些需要共用 React 元件；不要一開始製造同時控制金額、地圖、風險與表格的巨型 Card 元件。

## 第三層：功能專屬版型

| 功能 | 保留理由 | 與共同規則的接點 |
| --- | --- | --- |
| 價格定位 | 本案、成交、在售對照與價格軸適合空間比較 | 外部標題、金額單位、來源註記、程度徽章一致；圖軸、碰撞避讓與比較色保留 |
| 通勤／位置 | 地圖、起終點、路段及步行時間有自己的閱讀順序 | 表單與狀態提示一致；不把路線硬改成一般摘要卡 |
| 治安 | 分級、資料精度、犯罪組成需要同時被理解 | 色彩程度與來源標記可統一；五級刻度、町丁目／縣級差異保留 |
| 租買指南 | 搜尋、長文、流程、條件比較與 FAQ 各有用途 | 標題、搜尋、開合操作一致；時間軸和比較表各自保留 |
| PDF | 分頁、避免切卡、列印與固定頁首頁尾有專屬限制 | 共用視覺角色與資料語意，不與網頁共用同一套 DOM／排版尺寸 |
| 首頁／聯絡頁 | 品牌導入和聯絡操作的目的不同於分析報告 | 先獨立審視已有特殊字體、場景配色與互動，不讓閱讀頁整理意外改動品牌頁 |

## 區塊分類與第一批順序

「保留」代表保留資訊結構；如果內部存在共同規則差異，仍可做局部視覺整理。

| 區塊／檔案 | 分類 | 建議處理 |
| --- | --- | --- |
| `PageIntroCard`、`SectionHeading` | 調整視覺規則 | 保留兩種角色，檢查標題字體繼承、品牌色與圖示備援 |
| `RequirementAssessment`、`criteriaTagStyles` | 調整視覺規則，優先 | 分離分類色與程度色；保持所有評估文字與計算 |
| `listing/statusTheme` | 調整視覺規則，優先 | 對齊程度／資料狀態角色，維持未知狀態 fallback |
| `Guided*Fields`、`AdvancedCalculatorInputs` | 調整視覺規則 | 統一 label、欄位、選項、停用與 tooltip；引導與進階模式仍可有不同密度 |
| `SalePricePosition`、`SaleAgeComparison` | 保留 | 保留比較軸及圖形；只收斂標題、來源與數字層級 |
| `RentalInitialCostsSection`、`SaleInitialCostsSection` | 保留 | 保留分項明細與未知費用資訊，統一合計與來源層級 |
| `ListingLocationSection`、治安卡片 | 保留 | 保留地圖與分級結構；整理載入、錯誤與來源樣式 |
| `RentProcessSection`、`BuyProcessSection` | 調整視覺規則 | 保留步驟順序，處理節點形狀與同級標題，不重寫流程內容 |
| `BuySearchResults`、`RentSearchResults` | 調整視覺規則 | 搜尋結果標題、摘要與分類標籤共同化，保留不同資料來源 |
| `SalePriceFactors`、`SalePriceSources` | 需要重排資訊的候選 | 證據／估算／價格解釋較密集；先驗證手机閱讀順序與理解成本，再決定是否调整 |
| `InvestmentSection`、長篇限制說明 | 需要重排資訊的候選 | 檢查關鍵風險與假設是否容易被找到；不能為縮短畫面移除必要內容 |
| PDF、首頁／聯絡頁 | 保留，獨立驗證 | 網頁第一批完成後再檢查是否需要對齊共同角色 |

建議第一批落在「狀態／分類色 → 標題角色 → 表單與按鈕 → 明細與來源」；價格圖表、地圖、PDF 與長篇內容重排各自驗證，不與基礎規則同批混改。

## 每批的驗收方式

- 同用途的標題、欄位、徽章、來源和按鈕在租屋、買房、圖紙分析間能被辨認為同一套。
- 顏色都有明確角色；只看文字和圖示也能理解狀態與圖例。
- 桌機與手機逐頁檢查數字、日文名稱、長標題、tooltip、換行與開合狀態；增加或調整字級後重新確認資訊密度。
- 不改金額格式化、判斷條件、資料精度、API fallback 或請求有效性控制。
- 共用樣式遷移分批做，保留前後截圖，執行 TypeScript、相關互動測試及既有計算回歸測試。

本文件的來源為本地元件及 `src/index.css`。資訊重排屬設計假設，目前不宣稱已透過使用者測試或全站截圖證實。

- 驗證：TypeScript、21 組既有 test:* 全數通過；桌機與手機檢查共用元件。畫面測試使用合成資料，不呼叫 Gemini。

### 使用者視覺偏好修正

- `informationStyles.ts` 定義主要金額、明細金額、備註、來源、來源／估算標記、表頭、注意事項與載入提示的共同呈現角色。
- 租賃／買賣初期費用使用同一套明細金額、備註與注意事項樣式；未知費用文字、過濾條件、公式與格式化維持原樣。共用 DetailsToggle 保留受控展開狀態，補足焦點樣式與 44px 操作高度。

- 購屋預算摘要對齊金額層級，補充假設使用較清晰的文字；位置及治安載入提示增加 status 語意，定位錯誤保留原訊息與重試。
- 導言／區塊標題遵照使用者偏好保留原字體及綠色；地圖、PDF 與圖表專屬版型未改動。
- 驗證：27 個費用／預算／位置情境前後文字、表格列數與展開狀態一致；1440px／390px 畫面無新增水平溢出，費用表保留容器內水平捲動。TypeScript、21 組 test:*、建置通過。未呼叫 Gemini，亦未推送此批 UI。

## 可重複資訊元件化（續）

在 `src/components/ui/` 新增四個職責單一的元件：

| 元件 | 已套用位置 | 邊界 |
| --- | --- | --- |
| `CostSummary` | 租賃、買賣初期費用 | 共用摘要版型及操作位置；金額、單位、假設由原領域提供 |
