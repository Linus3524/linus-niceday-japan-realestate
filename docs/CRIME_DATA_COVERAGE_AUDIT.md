# 治安資料涵蓋範圍查核紀錄

查核日期：2026-09-11  
範圍：`src/lib/crimeSafety.ts`、`src/data/crimePrefectureSnapshot.ts`、`api/listing-crime.ts` 的資料來源選擇。

本文件記錄「為什麼東京是町丁目級、其餘 46 道府県只到都道府県級」的實際查證過程與結論，避免日後重複調查。結論基於當日實際下載到的檔案內容，不以推測或印象陳述。

## 結論

全日本並不存在統一的細粒度犯罪統計。町丁目級的**全罪種**資料目前僅東京都提供，因此系統採分層設計，並在 UI 明確標示精度差異。

| 層級 | 適用範圍 | 粒度 | 罪種 | 更新頻率 | 採用 |
| --- | --- | --- | --- | --- | --- |
| 町丁目級 | 東京都 | 町丁目 | 全罪種 | 月累計 | 是 |
| 都道府県級 | 47 都道府県 | 都道府県 | 全罪種（刑法犯） | 年度 | 是（東京以外） |

## 道府県警逐筆 CSV 不採用的三項理由

查證方式：BODIK CKAN API 檢索並實際下載 CSV 檢視標頭與資料列。

**① 僅涵蓋窃盗，且無人口分母**

實際取得的檔案為宮崎県「窃盗における手口別発生箇所一覧」與大分県「犯罪発生情報」，欄位結構近乎一致（皆源自警察庁範本）：

```
罪名,手口,管轄警察署（発生地）,管轄交番・駐在所（発生地）,市区町村コード（発生地）,
都道府県（発生地）,市区町村（発生地）,町丁目（発生地）,発生年月日（始期）,
発生時（始期）,発生場所の属性,現金以外の主な被害品
窃盗,部品ねらい,高岡,高岡,452017,宮崎県,宮崎市,高岡町花見,2018/3/1,17,駐車（輪）場,その他
```

`罪名` 僅有「窃盗」，不含強盜、傷害、性犯罪等。且為逐筆事件記錄而非統計表，聚合後只得到件數，沒有人口或世帯數作分母，無法判斷件數高是治安因素還是單純人流密集（如車站前商圈）。東京都的來源為官方已完成統計的全罪種認知件數，性質不同。

**② 資料時點過舊**

取得的兩份 CSV 資料日期均為 2018 年。東京都來源為月累計更新。兩者並列呈現會使使用者誤以為時點相當。

**③ 涵蓋率過低**

BODIK 以「窃盗」檢索全站僅 4 筆命中，其中含市級統計書與区級 XLSX，真正可用的縣級逐筆資料僅宮崎県、大分県。另查得熊本県「発生市町村別の犯罪率」為 XLSX 且僅到市町村級，格式再度不同。為 2/47 個縣維護專用解析器，效益與風險不成比例。

## 設計決策

- 兩種精度的型別刻意分離（`CrimeSafetyResult` / `PrefectureSafetyResult`），避免 UI 誤用為同等精度。
- 查詢結果以 `precision` 欄位標記（`"chome"` / `"prefecture"`），由 API 明確傳達。
- 都道府県級評等採「相對全國平均倍率」而非絕對件數；都道府県間人口基數差異過大，絕對值不可比。
- `PrefectureSafetyCard` 於卡片頂部固定顯示精度警語，說明該地區僅有都道府県層級統計。
- 東京都地址若因定位精度不足查無町丁目，退回都道府県級而非直接失敗。

## 已知限制

非東京物件僅能取得都道府県級概況，對「這條街是否安全」的參考價值有限。此為資料源限制，非實作取捨。

## 重啟評估的條件

出現下列任一情形時，`lookupCrimeSafety` 的分層結構可直接擴充，無須變更 API 介面：

- 警察庁釋出全國統一的町丁目級全罪種統計。
- 某道府県提供含人口分母的町丁目級全罪種資料且持續更新。
- 業務重心集中於已有逐筆資料的特定縣，且可接受「僅窃盗・年度較舊」的明確標註。
