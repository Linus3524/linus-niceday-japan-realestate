## 原因與修正

- 售價解析原先只讀「万」前數字，漏掉「億」部分；新增複合單位與全形數字處理。
- 面積解析原先只要整段出現「坪」就換算，讓「58.19㎡（17.60坪）」被錯算；改依匹配數值的單位，優先總面積及平方米。
- 新增 propertyType、landArea、buildingArea、roadDetails、hospitalityDetails、revenueDetails、revenueScope、taxDetails 原文欄位。
- 透天、整棟及住宿營業物件停用中古公寓成交／刊登行情高低價判定、公寓積立金與社區規模診斷。
- 民泊／旅館收益不再觸發「帶租約買賣」；專區呈現許可狀態、收益範圍、原始算式、刊載利回り與算術核對。
- 沒有營運成本明細，不提供民泊淨收益或淨投報率。收益不足或範圍不明時明示缺漏。
- 住宿用途不依建物面積直接確認自住減稅，也不自動套用住宅取得稅減免；取得稅等待登記用途與課稅分類確認，費用表標示未計入。
- 透天與整棟不套用公寓管修預繳；已列費用顯示為小計，另提示維護及營運預備金。
- 年度稅額保留圖紙年度及土地／家屋原文，程式合計可辨識的兩筆明載稅額。未刊載稅額仍可能由既有模型概算，不能視為納稅通知書金額。
- 圖纸「手数料1%／3%」不直接當買方應付費率；保留條件供核對委託契約。

## 驗證

- 修改前、後六張影像 API 均成功回應。
- `npm run test:special-sale`：六張的金額、類型、許可、收益範圍與不適用判定；另驗證一般公寓「民泊禁止」不會誤進特殊營業版型。
- `npm run test:sale-costs`、`npm run test:requirement-verdict`、`npm run lint`、`npm run build` 通過。
- 將修改後實際辨識結果接入完整上傳與分析畫面，在1440px桌機及390px手機逐張檢查；地圖API使用固定回應，未在這輪重測外部步行路由。
- CI 新增特殊買賣回歸，避免未來恢復錯誤分類與數值。

## 限制與依據

圖紙測試不等於確認真實許可或營收。AI 未來仍可能漏讀小字；核准文件、登記、道路與當前現況需另核對。原始圖紙及完整模型回應僅留在本機測試目錄，未加入版本控制。

住宿用途的提醒參照[觀光廳民泊制度與許認可分類](https://www.mlit.go.jp/kankocho/minpaku/overview/minpaku/index.html)；自住用途須確認的處理參照[東京都主稅局不動產取得稅](https://www.tax.metro.tokyo.lg.jp/kazei/real_estate/fudosan)。這些來源用來區分制度與適用前提，沒有以圖紙代替官方核准或稅額核定。
