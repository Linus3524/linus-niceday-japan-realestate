# 知識庫搜尋說明

租屋指南、買房置產與精選 Threads 的搜尋框，共用同義詞比對邏輯：[`src/lib/search.ts`](../src/lib/search.ts)。Threads 的相關度排序與 AI 推薦門檻集中在 [`src/lib/threadSearch.ts`](../src/lib/threadSearch.ts)。

## 行為

| 使用者輸入 | 結果 |
| --- | --- |
| `敷金` | 找出所有提到敷金的項目 |
| `敷金 禮金` | 找出**同時**提到兩者的項目（AND，順序不拘） |
| `敷金　禮金` | 同上（全形空白、逗號、頓號都當分隔符） |
| `押金` | 也會找到寫「敷金」的內容（同義詞） |
| `代書` | 也會找到寫「司法書士」的內容 |

- 每個關鍵字之間是 **AND**：全部命中才會顯示。
- 單一關鍵字內部是 **OR**：命中任一同義寫法即可。
- 租屋分頁需輸入 **2 個字以上**才啟動搜尋；買房分頁 1 個字即啟動。

## Threads 實務分享

- 租屋與買房搜尋結果下方最多顯示 3 篇 Threads 摘要卡片，站內知識與實務分享的數量分開呈現。
- 點「查看全部」會以 `#threads?search=關鍵字` 開啟完整精選頁並保留原查詢。
- AI 顧問由後端根據使用者問句與回答辨識已知概念，只在高相關度時回傳最多 2 篇；連結是系統資料，不由模型自行生成。
- 搜尋結果預設門檻是 52 分，AI 推薦預設門檻是 78 分。分數是站內排序尺度，不是機率或模型信心百分比。
- 卡片穩定顯示 0.8 秒後記錄一次曝光，點擊另外記錄；不儲存搜尋字詞或 AI 問句。

### 新增精選 Threads 文章

1. 將文章永久網址加入 `src/data/featuredThreads.ts` 的正確分類。
2. 執行 `npm run threads:sync`。此命令會同步全文搜尋索引與首張貼文圖片。
3. 執行 `npm run test:threads-search`，確認核心推薦案例仍正確。

完成後，精選文章頁、租屋／買房搜尋與 AI 顧問會共用同一份文章資料，自動納入新文章；
原文有公開圖片時，搜尋與 AI 推薦卡也會顯示首圖。若新文章使用尚未收錄的專有名詞，
仍應依下方維護原則補上同義詞，讓完整自然問句也能穩定辨識。

## 同義詞對照表

寫在 `src/lib/search.ts` 的 `SYNONYM_GROUPS`，同一組內的詞彼此等價。
目前涵蓋租屋初期費用、申請審查、退租，以及買房的價金、稅費、面積、物件型態與流程角色。

### 維護原則

1. **只放「講的是同一件事」的詞。** 制度上不同的東西不要放在一起——
   例如「手付金」是簽約時付的訂金，「頭期款」是自備款，兩者是分開的兩組。
2. **台灣慣用語可以對應日本制度**，即使只是功能相近（例如「代書 ↔ 司法書士」、
   「契稅 ↔ 不動產取得稅」）。這是為了讓台灣讀者搜得到，
   **不代表可以改寫內文的正式用詞**——內文仍要使用日本的正式名稱。
3. **新增知識庫內容時**，如果用了新的專有名詞，記得回來補一組同義詞。
4. 不要加入過於通用的詞（例如「費用」「日本」），會讓搜尋失去篩選效果。

### 加一組同義詞

在 `SYNONYM_GROUPS` 陣列裡加一行即可，順序不影響結果：

```ts
["定期借家", "定期租約", "定期契約"],
```

## 已知限制

- **沒有錯字容忍**：打錯字不會有結果（沒有模糊比對）。
- **一般知識卡沒有相關度排序**：租屋／買房知識卡依原本資料順序顯示；Threads 文章會依標題、開頭、人工關鍵字與內文命中位置加權排序。
- **AND 可能過嚴**：例如「火災保險 更新」會查無資料——
  知識庫裡有火災保險、也有更新料，但沒有同時談這兩件事的段落。這是預期行為。
- **查不到不一定是搜尋壞掉**，可能是知識庫真的沒有那個內容。
  判斷方式：直接用單一關鍵字查，若仍無結果，就是內容缺口，該補資料而不是改搜尋。
