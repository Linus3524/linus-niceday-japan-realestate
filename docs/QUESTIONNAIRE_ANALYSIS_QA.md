# 問卷 → 試算文字 → AI 分析驗證

日期：2026-11-10（日本時間）

## 執行方式

- `npm run test:questionnaire-analysis`：固定 seed 20261110，產生 160 組問卷條件，檢查文字格式、預算、地區、審查管道與解析補正的往返結果。不呼叫外部 AI。
- `npm run test:questionnaire-analysis -- --live=12`：同一批案例前 12 組，包含使用者回報案例與無設備／1DK 邊界案例，實際呼叫 `/api/rent-analysis` 的 handler、Gemini 與可行性計算。需本機 `.env.local` 的 AI 設定。
- `npm run test:find-home`：問卷格式、轉換與交接回歸。
- `npm run test:requirement-verdict`：可行性計算及已發現錯誤的回歸。

## 檢查範圍

月租上限、理想預算、初期費用；多選房型；空白與符號分隔地區、中日文地名、路線與車站；步行、屋齡、面積、結構；設備旗標及朝南／室內洗衣機；簽證類別、同住人數、境內／海外審查管道；入住期限／日期與入境日期的區分。

真實 AI 案例也檢查沒有勾選的設備不能憑空變成需求，以及初期費用相對月租上限的倍數。

## 已修正的問題

| 問題 | 修正 |
| --- | --- |
| 高圓寺被放在行政區欄位，已有杉並區行情仍被判查無行情 | 地點欄位統一校正、對應車站所在行政區，保留真正未知地點 |
| 多選房型使初期費用 100 萬覆蓋月租上限 25 萬 | 多方案預算只取月租條件，初期費用與押金等金額排除 |
| 山手線被擷取成橫濱的山手站 | 車站名稱後接「線」時視為路線提及，真正的山手站仍可辨識 |
| 問卷 1DK 被轉成 1LDK 群組 | 與試算的 1K／1DK 計價群組一致 |
| 朝南、室內洗衣機可能被模型漏掉 | 從明確文字補回未設專屬旗標的需求，加入條件說明 |
| 境內／海外審查管道未從問卷文字保留；單人同住資訊省略 | 明確帶入居住地及人數，對應審查管道 |
| AI 把入境日期當作入住日期 | 文字中明確的「入住時間」優先於模型結果 |

## 驗證界線

這些測試驗證資料傳遞與計算一致性，不代表實際空房供給。AI 仍有隨機性；真實呼叫屬抽樣整合測試。多選房型目前仍依系統既有規則，以最大房型作單一分析基準，並在結果中提示。

本文件記錄本機程式與真實 AI 的驗證結果；未以瀏覽器操作正式站 UI。部署狀態以 GitHub／Vercel 為準。CI 會執行不連外部 AI 的 160 組固定種子測試。
